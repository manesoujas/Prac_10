PROJECT TITLE: 
CampusEvents - College Event Management Platform

AIM:
To design and develop a full-featured MERN stack web application for creating, managing, and registering for college events, including an administrative dashboard, secure authentication, and role-based access control.

BRIEF DESCRIPTION:
CampusEvents is a robust, modular web platform built for seamless event operations across educational institutions. 
It operates on three core user roles:
1. Students: Can intuitively discover and register for technical, cultural, and sports events. 
2. Organizers: Empowered to securely construct nested event structures, manage participant capacities, and update configurations. 
3. Administrators: Maintain global oversight, including the capability to officially approve pending event drafts and publish them to the public grid.
The platform ensures data security using JWT authentication and prevents overlapping registrations using strict database validations.

TECHNOLOGIES USED:
- Frontend: React.js, Vite, Axios, Framer Motion (Scroll Animations), Vanilla CSS
- Backend: Node.js, Express.js
- Database: MongoDB (NoSQL) & Mongoose (ODM)
- Security: JSON Web Tokens (JWT) & Bcrypt Encryption

CORE LOGIC:
1. Authentication Logic:
   The system uses JSON Web Tokens passed securely in HTTP Headers. The backend strictly verifies tokens during route execution. The `/api/users/me` endpoint dynamically reconstructs the user's role on reload.

2. Event Hierarchy & Database Validation:
   Organizers can recursively link child events (like competition rounds) to a main parent event using MongoDB ObjectIds. Database checks prevent casting errors if parents are left blank.

3. Role-Based Access Control (RBAC):
   Backend Middleware explicitly evaluates exactly what role a user holds ('student', 'organizer', or 'admin'). An organizer is blocked from tampering with events they do not own.

4. Pending Event Sandbox Security:
   Newly formulated events are forced into a segregated 'pending' database state. They remain invisible to standard students and are blocked from the main grid until an Administrator overrides their enum state to 'published'.

IMPORTANT CODE:

Below is the backend controller logic used to securely map an Event payload into the Database:

export const createEvent = async (req, res) => {
    try {
        const { title, parentEvent, rootEvent } = req.body;
        
        // Dynamically apply approval states based on security profile
        const eventData = { 
            ...req.body, 
            organizer: req.user._id, 
            status: req.user.role === 'admin' ? 'published' : 'pending' 
        };
        
        // Prevent Mongoose CastErrors from empty dropdown strings
        if (!eventData.parentEvent) delete eventData.parentEvent; 
        if (!eventData.rootEvent) delete eventData.rootEvent; 
        
        const event = await Event.create(eventData);
        res.status(201).json({ success: true, data: event });
    } catch (error) {
        res.status(500).json({ success: false, message: error.message });
    }
};

2. Frontend Route Protection (React Context & Router):
This snippet demonstrates how the React frontend shields secure pages from unauthorized users utilizing Context API.

const ProtectedRoute = ({ children, allowedRoles }) => {
    const { user, loading } = useAuth();
    if (loading) return <div>Loading...</div>;
    if (!user) return <Navigate to="/login" />;
    if (allowedRoles && !allowedRoles.includes(user.role)) {
        return <Navigate to="/unauthorized" />;
    }
    return children;
};

// Inside App.jsx routing component:
<Route path="/admin/dashboard" element={
    <ProtectedRoute allowedRoles={['admin']}>
        <AdminDashboard />
    </ProtectedRoute>
} />
