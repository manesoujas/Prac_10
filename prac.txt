Project Title: CampusEvents - College Event Management Platform

Aim:
To design and develop a full-featured MERN stack web application for creating, managing, and registering for college events, focusing on hierarchical event structures, animated user interfaces, and role-based access control.

Brief Description:
CampusEvents is a robust, modular platform built for seamless event operations across educational institutions. It allows Students to intuitively discover and register for technical, cultural, and sports events. Organizers are empowered to securely construct nested event structures, manage participant capacities, and update configurations. Administrators maintain global oversight, including the capability to officially approve pending event drafts to publish them to the public grid.

Technologies Used:
- Frontend: React.js, Vite, Axios, Framer Motion (Scroll Animations), Vanilla CSS
- Backend: Node.js, Express.js, Mongoose
- Database: MongoDB (Local/Atlas)
- Security: JSON Web Tokens (JWT), Bcrypt Encryption
- Utilities: qrcode.react (QR Generation), react-toastify (UI Notifications)

Project Structure:

    |-- /models (Mongoose Schemas: User, Event, Registration)
    |-- /routes (API Network Endpoint Configuration)
    |-- /middleware (Auth & Security Validation Gates)
    \-- server.js (Main Express Execution Core)

Core Logic:
1. Authentication: Uses JWT tokens passed securely in HTTP Headers. The /api/users/me endpoint dynamically reconstructs the user's state on reload.
2. Event Hierarchy: Organizers can recursively link child events (like competition rounds) to a main parent event using MongoDB ObjectIds.
3. Role-Based Access Control (RBAC): Backend Middleware strictly verifies `req.user.role` as either 'student', 'organizer', or 'admin' before permitting document operations.
4. Pending Event Safety: Newly created events are forced into a isolated 'pending' database state. They will never crash or leak into the standard grid until administrators override them to 'published'.

Important Code Snippets:

1. Event Creation & Sanitization (Backend Controller):
```javascript
export const createEvent = async (req, res) => {
    try {
        const { title, parentEvent, rootEvent } = req.body;
        const slug = slugify(title, { lower: true, strict: true }) + '-' + Date.now();
        // Dynamically applies approval states based on security profile
        const eventData = { ...req.body, slug, organizer: req.user._id, rootEvent, status: req.user.role === 'admin' ? 'published' : 'pending' };
        
        // Prevent Mongoose ObjectId CastErrors from empty dropdown strings
        if (!eventData.parentEvent) delete eventData.parentEvent; 
        
        const event = await Event.create(eventData);
        res.status(201).json({ success: true, data: event });
    } catch (error) {
        res.status(500).json({ success: false, message: error.message });
    }
};
```
